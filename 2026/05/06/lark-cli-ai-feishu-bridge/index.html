Lark-CLI：让 AI 真正用上飞书

PUBLISHED 2026.05.06
AI Coding Claude Code 工程实践 Lark-CLI 飞书

你是否曾经想过，直接把产品经理的飞书需求文档发给 Claude Code（OpenClaw、Codex、Cursor、Kiro CLI、Qoder、Trae、Windsurf），让 AI 直接理解产品需求，再根据 Codebase 设计技术方案。你校准满意后再让 AI 开始干活，坐等验收。

理想很美好，现实很骨感。第一个问题是 AI 没有飞书的访问权限，对此公司内有团队开发出了知言 MCP（doc-parser），可以让 AI 把飞书文档提取成 Markdown，方便喂给 AI。

一、Lark-CLI

飞书在 GitHub 上开源了一个命令行工具 larksuite/cli，叫 lark-cli。

飞书 CLI 覆盖了飞书 11 个核心业务域，包括即时通讯、云文档、多维表格、电子表格、日历、邮箱、任务、视频会议、知识库、通讯录、云空间，总共提供了 200 多条命令。

几乎把飞书核心能力都包进来了。

同时它还为 AI Agent 设计了 19 个预置 Skills，相当于 19 套指令文件，AI 加载之后就知道怎么调用飞书的各项功能，不需要你来帮它选工具。

天然适合 AI 操控

CLI 的本质是命令，一行命令做一件事，结构清晰。这和 AI 的交互方式高度吻合——AI 最擅长的就是把你的自然语言翻译成一条条命令，然后顺序执行。

基于 OpenAPI 的 MCP 之所以上下文爆炸，是因为它把所有 API 都平铺出来，AI 要从几十上百个选项里挑合适的。而 CLI 是把这些 API 组合成了有意义的命令单元，一条命令背后可能封装了三四个 API 调用，AI 不需要知道细节，只需要知道用哪条命令。

不需要自己开发

以前要自己写脚本封装成 CLI 命令，现在现成的命令直接用。

二、安装步骤

把下面这句话发给你的 AI Agent（Claude Code、Codex …）。AI 会自动安装 @larksuite/cli 以及 19 个 Skills。

中间会进行飞书应用凭证配置和登录授权。点击 URL，跳到网页点击授权后，飞书会自动上报审批权限。

通过后就完成了全部配置，你就收获了一个机器人。

装完之后，要重启 Claude Code（或者 Cursor、Codex 等），才能加载 Skills。

具体指令步骤：

安装后的 lark-cli 在 ~/.nvm/versions/node/v20.20.2/bin/lark-cli 中，是一个 Node.js 脚本，用来启动真正的 CLI 程序。

安装后所有的 Skills 在 ~/.agents 文件夹下。在线 Skills 仓库：skills.sh/larksuite/cli

感兴趣可以详细看看 skill.md 的详细设计：

所有的配置信息在 ~/.lark-cli 中：

  • ~/.config/lark-cli/config.json — 应用凭证（App ID、App Secret）
  • ~/.config/lark-cli/cache/ — Token 缓存（包含你的 OAuth 授权 token）
  • ~/.config/lark-cli/logs/ — 日志
  • ~/.config/lark-cli/locks/ — 锁文件

四、可以做什么

仅介绍个人觉得实用的功能，更全面的功能请探索 Lark-CLI 官方开发文档。

（一）总结群聊消息

AI 会决定执行什么 Skill 命令，自动读取群消息。适用于需求讨论群、技术方案讨论群的消息总结，归纳成需求背景。

（二）读取需求文档和技术文档

第三方飞书文档读取工具最大的问题是，对于从飞书文档里提取内容，结果拿回来的只有纯文本，图片没了，表格结构没了，画板没了，文档排版全丢了，基本上就是把所有富文本内容打平成一段话。

Lark-CLI 原生支持读取富文本，从命令输出可以看出，Lark-CLI 可以直接读取文档源码进行解析，从而能够更好地理解需求文档。

测试对文档中时序图画板的理解，会自动调用工具读取，解析得很好。

最终可以准确地把需求文档和技术文档综合成 Markdown 文件。

（三）总结业务代码，整理成飞书文档

为了在业务需求生命周期末尾总结技术方案，往往需要根据代码设计沉淀出业务文档，作为团队知识库，方便不同业务同事快速了解。

相比飞书 MCP，通过 CLI 方式读取到的文档内容结构更完整，包含了图片 token、流程图、代码块等富文本内容。

支持 40+ 种块类型，Markdown 导入飞书之后再导出，内容完整保留，没有损耗。更夸张的是，文档里的 Mermaid 和 PlantUML 图表（支持 8 种图表类型），写入飞书后会自动转成飞书画板——不是截图，是可以直接在飞书里编辑的矢量图。

这对写技术文档的人来说很实用。本地写好的 Markdown 文档，一条指令写进飞书，格式完整保留；反过来，飞书里已有的文档直接拉下来给 AI 读，结构也不会丢——图片、表格、画板全在，不再是打平的纯文本。

注意事项

Lark-CLI 本质上是打通 LLM 和飞书之间的鸿沟，使得 LLM 可以访问飞书进行实际操作。LLM 使用公司内部的 ept-claude 或者 siada，安全风险应该不存在问题，但也需注意，仅供参考。
